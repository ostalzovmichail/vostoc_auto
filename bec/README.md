# Axum Server

Высокопроизводительный сервер на Rust (Axum) с модульной архитектурой, авто-документацией API и структурированным JSON-логированием.

## Предварительные требования

- **Rust** (последняя стабильная версия): `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`

## Структура проекта

```
src/
├── main.rs              # Точка входа: конфиг -> логирование -> БД -> роутер -> сервер
├── api/
│   ├── mod.rs           # AppState — общее состояние (БД + конфиг) для обработчиков
│   ├── router.rs        # Сборка роутера: маршруты, Swagger (dev), CORS, трассировка
│   ├── models.rs        # ApiResponse/helper'ы + реэкспорт моделей данных (Car/Stats/Contact)
│   ├── templates.rs     # Шаблоны askama: HTML-фрагменты для страниц на htmx
│   └── handlers/
│       ├── basic.rs     # Эндпоинты: /, /test, /db
│       ├── cars.rs      # JSON API: /api/cars, /api/cars/latest, /api/cars/sold, /api/stats, /api/contacts
│       ├── admin.rs     # Админ-API (запись): /api/admin/cars — добавление, удаление, статус, фото
│       └── pages.rs     # HTML-фрагменты: /partials/hero, /partials/catalog, /partials/sold, ...
└── core/
    ├── config.rs        # Конфигурация: окружение (dev/prod), валидация переменных
    ├── db.rs            # Трейт Database + реализация на SQLite (sqlx)
    ├── models.rs        # Модели данных: Car, Stats, Contact + display-хелперы и фильтр каталога
    └── logging.rs       # JSON-логи с ротацией по датам: logs/YYYY/MM/DD/

templates/partials/      # Шаблоны askama (компилируются вместе с крейтом)
static/images/           # Фотографии автомобилей (раздаются по /images)
frontend/                # Новый фронтенд: HTML + CSS + htmx (раздаётся по /ui/)
```

Каталог `static/images/` — статика (фотографии автомобилей), раздаётся по `/images`. В БД (таблица `car_images`) хранятся относительные пути; абсолютный адрес (хост API) подставляет фронтенд, поэтому данные не привязаны к окружению.

Слои зависят только внутрь: `handlers` → `api::AppState` → `core`. Обработчики знают о БД через трейт `Database`, а не через конкретную реализацию — SQLite можно заменить на PostgreSQL, не трогая остальной код.

## Фронтенд

Фронтенд разбит на файлы и работает на [htmx](https://htmx.org): страница не запрашивает JSON, а получает с сервера готовые HTML-фрагменты и вставляет их в разметку.

```
frontend/
├── index.html           # Каркас страницы + hx-* атрибуты (что и куда подставлять)
├── css/                 # Стили по блокам: base, header, hero, catalog, sold, stats, process, contacts, responsive
├── js/app.js            # Только анимации и UX: reveal, счётчики, галерея, форма
└── vendor/htmx.min.js   # htmx (лежит локально — страница работает без CDN)
```

Почему так:

- **CSS разделён по секциям** — правки в одном блоке не задевают остальные, порядок подключения задан в `index.html`.
- **`app.js` не рисует данные.** Разметку собирает сервер шаблонами `askama` (`templates/partials/*.html`), поэтому данные берутся из БД теми же моделями, что и JSON API. Опечатка в шаблоне — ошибка сборки, а не 500 в проде.
- **Сервер раздаёт фронтенд сам** (`/ui/`), поэтому страница и фрагменты живут на одном origin: htmx ходит относительными путями, CORS не нужен.

Взаимодействие:

| Блок | Запрос | Приём |
|---|---|---|
| Главный акцент | `GET /partials/hero` | `#heroBody` |
| Каталог | `GET /partials/catalog?status=&q=&sort=` | `#carGrid` (+ счётчики фильтров через `hx-swap-oob`) |
| Проданные | `GET /partials/sold` | `#soldRow` |
| Статистика | `GET /partials/stats` | `#statsGrid` |
| Контакты | `GET /partials/contacts` | `#contactsBody` (+ телефон в шапке через `hx-swap-oob`) |

Фильтры каталога (статус, поиск, сортировка) живут вне области подстановки, поэтому не сбрасываются при обновлении списка.

Открыть: <http://localhost:8080/ui/>.

Просмотры страницы `/ui/` считаются в счётчике посещений: его числа доступны только администратору через `GET /api/admin/stats/visits` и не отображаются на сайте.

> Папка `disain/` в корне репозитория — исходный макет-референс («ВОСТОК АВТО» одним файлом). Она остаётся как есть и не используется сервером.

## Конфигурация

Конфигурация читается из переменных окружения, файлы `.env.*` подключаются как источник значений.

**Порядок приоритета**: системное окружение > `.env.{APP_ENV}` > `.env` (`dotenvy` не перезаписывает уже заданные переменные).

Создайте файлы конфигурации из шаблона:
```bash
cp .env.example .env.dev   # для разработки
cp .env.example .env       # для продакшена
```

> Значения с пробелами (например, `START_MESSAGE="Авто API"`) обязаны быть в кавычках —
> этого требует парсер `dotenvy`. Строка без кавычек считается ошибкой разбора,
> и переменная в итоге не задаётся.

| Переменная | Обязательна | Описание |
|---|---|---|
| `APP_ENV` | нет | `dev` (по умолчанию) или `prod`. Неизвестное значение — ошибка при старте |
| `DATABASE_URL` | да | Строка подключения к БД, напр. `sqlite:./sqlite.db`. SQLx не создаёт файл БД сам: для новой базы добавьте `?mode=rwc` или создайте файл заранее |
| `SERVER_HOST` | да | Адрес привязки: IP или имя хоста (`127.0.0.1`, `localhost`) |
| `SERVER_PORT` | да | Порт, число 0–65535 |
| `START_MESSAGE` | да | Приветственное сообщение при старте |
| `CORS_ALLOWED_ORIGINS` | нет | **Только prod**: разрешённые origin'ы через запятую. Пусто — CORS-заголовки не отдаются, чужие origin'ы блокируются браузером |
| `ADMIN_TOKEN` | нет | Токен приложения управления (заголовок `X-Admin-Token`). Не задан — маршруты `/api/admin/*` отвечают `503`, а сайт работает как обычно |
| `IMAGES_DIR` | нет | Каталог фотографий (по умолчанию `static/images`). Один и тот же для раздачи `/images` и для сохранения фото из админ-API |
| `RUST_LOG` | нет | Переопределяет фильтр логирования (напр. `info,tower_http=warn`) |

## Запуск

### Разработка (по умолчанию, порт 8080)
```bash
cargo run
```

### Продакшен
```bash
APP_ENV=prod cargo run
```

При остановке по `Ctrl+C`/`SIGTERM` сервер дообрабатывает текущие запросы и завершается корректно (graceful shutdown).

## API и документация

| Эндпоинт | Описание |
|---|---|
| `GET /` | Базовая проверка сервера |
| `GET /test` | Тестовый эндпоинт |
| `GET /db` | Проверка подключения к БД (возвращает только успех/ошибку, без внутренних деталей) |
| `GET /api/cars/latest` | Последнее добавленное авто (акцент на главной) |
| `GET /api/cars?status=stock&limit=50&offset=0` | Автомобили в продаже. Фильтр `status`: `stock`, `transit`, `order`; без фильтра — всё, кроме проданных. `limit` 1–100, `offset` от 0 |
| `GET /api/cars/sold` | Проданные автомобили (свежие сделки первыми) |
| `GET /api/stats` | Статистика базы: всего / в наличии / в пути / под заказ / продано |
| `GET /api/contacts` | Контактная информация автосалона |
| `GET /api/admin/cars?status=&limit=&offset=` | **Админ-API.** Все автомобили, включая проданные. Требует `X-Admin-Token` |
| `POST /api/admin/cars` | **Админ-API.** Добавить авто (JSON). Номер лота сервер присвоит сам, если не передан |
| `PATCH /api/admin/cars/:id/status` | **Админ-API.** Сменить статус (`stock`/`transit`/`order`/`sold`). При `sold` проставляются дата продажи и срок сделки |
| `DELETE /api/admin/cars/:id` | **Админ-API.** Удалить авто вместе с фотографиями (файлы тоже удаляются) |
| `POST /api/admin/cars/:id/images` | **Админ-API.** Загрузить фото (multipart, поле `file`; JPEG/PNG/WebP до 15 МБ) |
| `DELETE /api/admin/cars/:id/images?url=/images/...` | **Админ-API.** Удалить одно фото |
| `GET /api/admin/stats/visits` | **Админ-API.** Счётчик посещений сайта: всего / сегодня / за 7 дней. На публичной странице не показывается |
| `GET /images/<путь>` | Статические файлы из `static/images/` — фотографии авто. Пример: `/images/honda-xr-v-2023/honda-xr-v-2023-1.jpeg` |
| `GET /ui/` | Страница фронтенда (HTML + CSS + htmx) из `frontend/` |
| `GET /partials/hero` | HTML-фрагмент: главный акцент с последним авто |
| `GET /partials/catalog?status=&q=&sort=` | HTML-фрагмент: карточки каталога. `status`: `stock`,`transit`,`order`; `q` — поиск; `sort`: `new`,`price-asc`,`price-desc`,`mileage` |
| `GET /partials/sold` | HTML-фрагмент: архив проданных |
| `GET /partials/stats` | HTML-фрагмент: счётчики статистики |
| `GET /partials/contacts` | HTML-фрагмент: контакты и форма звонка |

Эндпоинты `/partials/*` отдают **HTML**, а не JSON: их запрашивает htmx и вставляет в страницу.
`/api/*` и `/partials/*` держим в разных префиксах намеренно — не смешиваем форматы ответа.

Поле `image_url` у авто — относительный путь (`/images/...`); полный список фото объявления — в поле `images` (массив, первое — обложка).

Эндпоинты `/api/*` отдают данные как JSON напрямую (массив авто, объект статистики, объект контактов).
Ошибки — в едином формате `{ "status": "error", "message": "..." }`: `404` если данных нет,
`400` при недопустимом `status`, `500` с generic-сообщением при сбое БД (детали — только в логах).

- **Swagger UI**: `/swagger-ui` — **только в dev-режиме**, в проде документация отключена
- **OpenAPI JSON**: `/swagger-ui/openapi.json`

Формат ответа единый:
```json
{ "status": "success", "message": "..." }
```
При серверных ошибках возвращается `500` и generic-сообщение, детали — только в логах.

## Админ-API и приложение управления

Публичные маршруты (`/api/*`, `/partials/*`) только читают данные. Менять каталог
можно через `/api/admin/*` — эти маршруты требуют заголовок `X-Admin-Token`
со значением `ADMIN_TOKEN` и сравнивают его за постоянное время
(чтобы токен нельзя было подобрать по времени ответа).

- **Токен не задан** → все `/api/admin/*` отвечают `503`: честнее сказать
  «не настроено», чем оставить запись данных открытой.
- **Неверный токен** → `401`.
- Префикс `/api/admin/*` выбран намеренно: админ-маршруты не должны выглядеть
  как публичные.

Готовый клиент — приложение на Flutter в `../admin_app` (Android, iOS, Windows,
Linux, macOS, Web): добавление и удаление авто, смена статуса, загрузка фото.
Подробности — в `../admin_app/README.md`.

Пример: добавить авто и отметить проданным.

```bash
TOKEN=$(grep ADMIN_TOKEN .env.dev | cut -d= -f2)

curl -X POST http://127.0.0.1:8080/api/admin/cars \
  -H "X-Admin-Token: $TOKEN" -H 'Content-Type: application/json' \
  -d '{"brand":"Lada","model":"Vesta","year":2022,"mileage":30000,"engine":"1.6 (106 л.с.)","transmission":"MT","drive":"FWD","price_rub":1200000}'

curl -X PATCH http://127.0.0.1:8080/api/admin/cars/15/status \
  -H "X-Admin-Token: $TOKEN" -H 'Content-Type: application/json' \
  -d '{"status":"sold","delivery_city":"Москва"}'
```

## Логирование

JSON-логи с ротацией по датам: `logs/YYYY/MM/DD/`
- `info.json` — информационные события
- `debug.json` — подробные логи (в проде не пишется: фильтр `info`)
- `others.json` — предупреждения и ошибки

Файлы логов создаются с правами `600` (только владелец). Консоль: в dev — всё, в prod — только WARN/ERROR.
